# Issue Tracker: Beads

Issues, specs, triage state, and dependency edges for this repo live in Beads (`bd`). Do not create GitHub issues, local markdown issue files, TodoWrite lists, or task files as the durable tracker.

External pull requests are not a request surface for this repo.

## Before Working

Refresh tracker context:

```bash
bd prime
bd ready
```

Inspect a ticket before editing:

```bash
bd show <id> --json
```

Claim a ticket when starting implementation:

```bash
bd update <id> --claim
```

## When a Skill Says "Publish to the Issue Tracker"

Create Beads issues in dependency order, blockers first:

```bash
bd create --title="Short action title" \
  --description="Why this issue exists and what needs to be done." \
  --acceptance="Observable criteria for closing the issue." \
  --type=task \
  --priority=2 \
  --labels=ready-for-agent
```

Use native Beads dependency edges instead of prose-only "blocked by" sections:

```bash
bd dep add <blocked-issue> <blocking-issue>
```

For a parent effort, create an epic first and attach children:

```bash
bd create --title="Parent effort" --type=epic --priority=1
bd create --title="Child slice" --type=task --priority=2 --parent=<epic-id>
```

## When a Skill Says "Fetch the Relevant Ticket"

Read the issue and dependency graph from Beads:

```bash
bd show <id> --json
bd comments <id> --json
```

Use `bd ready` for the frontier: a ticket is ready when all blocking dependencies are closed and it is not deferred.

## Triage Operations

Apply category labels with Beads labels:

```bash
bd label add <id> bug
bd label add <id> enhancement
```

Apply exactly one state label from `docs/agents/triage-labels.md`:

```bash
bd label add <id> ready-for-agent
bd label remove <id> needs-triage
```

If the triage outcome needs a note, use Beads comments:

```bash
bd comments add <id> -f <notes-file>
```

For Matt Pocock's `triage` skill, any generated triage comment must begin with:

```markdown
> *This was generated by AI during triage.*
```

Close only when the issue is truly finished or intentionally rejected:

```bash
bd close <id> --reason="Completed: ..."
bd close <id> --reason="Wontfix: ..."
```

## Wayfinding Operations

Use a Beads epic as the map and child issues as investigation tickets.

- Map: one `epic` issue containing the destination, fog, decisions so far, and acceptance criteria.
- Child ticket: one Beads `task`, `spike`, or `decision` issue per investigation question.
- Claim: `bd update <id> --claim`.
- Resolve: update the child with the answer in `--notes` or a comment, then close it.
- Frontier: `bd ready` shows unblocked children.

Record durable conclusions in the epic or in ADR/domain docs when they become project conventions.

## Sync and Publishing

This repo currently has no Git or Dolt remote configured. Do not run `bd dolt push`, `git push`, or publish tracker state unless the user explicitly asks and a remote exists.
